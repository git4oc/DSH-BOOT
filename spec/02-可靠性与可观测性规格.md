## 1. 角色职责与边界

### 1.1 本规格管什么

| 主题 | 覆盖内容 | 需求段 |
|---|---|---|
| SLO 可测量化 | 分子 / 分母 / 测量点 / 排除项 / 归因 / 数据来源六元组；错误预算归因不跨方 | `REL-001`–`REL-027` |
| 恢复路径分 span | 拿锁 / 读+closer / 折叠 / connector 就绪 / 工具集就绪各自的埋点与预算 | `REL-028`–`REL-036` |
| 降级阶梯 | L0 / L1 / L1b / L2 / L3 的进入退出阈值、滞回与最短驻留、跨作用域聚合、软依赖不阻断 | `REL-037`–`REL-051` |
| 缓冲与墓碑 | 计费与审计分缓冲、按时间定容、抖动补传与令牌桶、领先指标、有界丢弃 | `REL-052`–`REL-059` |
| 故障域与爆炸半径 | 矩阵可演练、`N_node = min(内存约束, 爆炸半径约束)` 的数字来源、跨租户反亲和 | `REL-060`–`REL-068` |
| 恢复与迁移 | 追加 closer 语义、副作用台账写入时机与恢复后处置、迁移状态机与 fencing | `REL-069`–`REL-089` |

| 轮次三层截止时间 | `T_a` / `T_m` / `T_turn` 的生效点、超时行为、挂死轮次 | `REL-102`–`REL-110` |
| 演练门禁 | 最小演练集 6 项的可执行用例与留证 | `REL-111`–`REL-120` |

### 1.2 本规格不管什么（明确指向其他 SPEC）

| 不管的内容 | 归属 |
|---|---|
| 威胁模型、TCB 边界、强制链与拦截点的**安全语义** | `SEC-###`（例：`SEC-012` 注册桥入口拦截、`SEC-069`/`SEC-070` 最小审计集） |
| 凭证签发与例外登记、出站授权、沙箱模式与 preset 变更的审批语义 | `SEC-###`（例：`SEC-023` 升权上限、`SEC-055` 凭证例外） |
| **最小审计集的成员定义**（本规格只规定其不可用时的级别与行为） | `SEC-069`、`SEC-070` |
| 域就绪判据 7 条的**检查内容**（本规格只规定其失败时的级别为 L3） | `SEC-037`–`SEC-044` |
| 计费与审计的**独立缓冲与有界丢弃行为本体**（本规格只规定其参数与 SLO） | `SEC-075` |
| 审计不可篡改（哈希链 / WORM / 取证包）与 DSR / 删除证明的安全语义 | `SEC-072`、`SEC-085`、`SEC-090` |
| 代码结构、反转面实现细节、契约测试、CI 门禁与 DevEx | `ENG-023`、`ENG-031`、`ENG-035`、`ENG-046`、`ENG-051` |
| 用户可见文案、SLA 条款措辞、赔偿与定价、SKU 承诺 | `PRD-017`、`PRD-034`、`PRD-037`、`PRD-050`、`PRD-051`、`PRD-052` |
| 版本兼容面、格式版本策略、依赖弃用流程、备份拓扑与驻留区域 | `EVO-007`–`EVO-010`、`EVO-019`、`EVO-026`、`EVO-027` |

> `SEC-###` / `ENG-###` 的段位形式仅用于**整域排除**（其内部条目由对应规格分配）；凡本规格有具体消费点的引用一律写具体 ID。跨版本引用失效时，按 `SPEC-00` §4.2 保留编号、升次版本并回填。

## 2. 规范性条款

### 2.1 SLO 的可测量化

| ID | 级别 | 条款 | 验收判据 | 依据 | 拦截点 / 测量点 |
|---|---|---|---|---|---|
| `REL-001` | 必须 | 每条 SLO 必须以「分子 / 分母 / 测量点 / 排除项 / 归因 / 数据来源」六元组登记于《SLO 登记表》，缺任一项不得发布 | 对《SLO 登记表》逐条做字段完整性校验，缺项即失败；并抽 3 条在预发按登记口径复算，复算值与登记值偏差须落在测量误差容许带内 | §9.1 | SLO 登记表 schema CI 校验 + 预发复算 |
| `REL-002` | 必须 | 「控制面可用性」按 `1 − 平台责任失败请求数 / 总请求数` 计算，且平台责任 / 模型责任 / 策略 fail-closed 三类失败必须**分列**展示 | 注入：模型网关对全部请求返回 5xx 持续 5 min；观察：控制面可用性不得跌破 99.9%，且失败分列面板中「模型责任 > 0」而「平台责任 = 0」 | §9.1、G2 | 网关访问日志 + 责任方分类器 |
| `REL-003` | 不得 | 「控制面可用性」与「网关可用性」不得作为两条独立 SLO 分别计数 | 检索《SLO 登记表》，存在两条分母相同、仅名称不同的可用性 SLO 即失败 | §9.1（已删除项） | SLO 登记表 CI 校验（分母去重键） |
| `REL-004` | 必须 | 「平台首 token 开销 P95 ≤ 400 ms」必须由两个测量点组成：①反向网关收到请求 → 上游发出；②上游首字节 → SSE 首帧写出 | 注入：上游固定增加 2 s 延迟；观察：该指标 P95 相对基线变化 ≤ 50 ms（即不包含上游耗时）；两段 span 必须分别可见 | §9.1 | span `gw.upstream_send` + span `gw.sse_emit` |
| `REL-005` | 必须 | 「端到端首 token P95 ≤ 3 s」的「首 token」必须定义为首个 `message.delta`；`reasoning.delta` 必须单列指标；归因必须标为「按模型」 | 注入：上游模型固定返回 5 s TTFT；观察：端到端首 token P95 超阈但**平台错误预算消耗 = 0**；且 reasoning 首 token 出现在独立指标中 | §9.1、G2 | SSE 事件时间戳 − 用户发送时间戳；指标 `slo.first_token.e2e_p95` |
| `REL-006` | 必须 | 「轮次成功率」分子 = `turn.completed` 数；分母 = 全部 turn − `turn.cancelled`（用户取消在分子分母同时扣除）；`turn.interrupted` 与挂死轮次必须计入分母并计为失败 | 注入：连续 100 次用户取消 + 10 次 `kill -9` 中断；观察：成功率分母 = 110 − 100 = 10，分子 = 0，指标为 0% 而非 100% | §9.1、C22 | 域外轮次终态记账器 |
| `REL-007` | 必须 | 每个 turn 必须在 `T_turn` + 60 s〔待压测回填〕内落终态；无终态 turn 计入分母并计为失败 | 注入：轮次看护进程被杀（不再发终态）；观察：`turn.unterminated.count` 增加，成功率分母包含该 turn 且标为失败 | §4.4.1、§9.1 | 域外轮次终态收敛看护 |
| `REL-008` | 必须 | 「内核日志恢复 RTO ≤ 30 s @ ≤10⁵ 事件」的测量点必须是「进程启动 → 用户下一次 turn 被接受」，**禁止**以 `open`（拿锁）完成或日志读取开始作为测量点 | 注入：对持有 10⁵ 事件的会话进程 SIGKILL，立即重启；观察：到该会话首个 `turn.started` 被接受的耗时 ≤ 30 s；若以拿锁点计量则本判据不成立（必须能从 span 拆解中证明拿锁占比） | §9.1、C21、C22 | Session Router turn 准入时间戳 − 进程启动时间戳 |
| `REL-009` | 必须 | 内核日志恢复 RTO 必须按日志规模分档测量（≤10⁴ / 10⁵ / 10⁶ 事件），每档独立给出目标值〔待压测回填〕与样本量 | 交付分档表：每档含事件数、目标值、实测 P50/P95/P99、样本量；用 ≤10⁴ 档的成绩代替 ≤10⁵ 档报告即失败 | §9.1、§9.2 | 分档压测报告 + 指标 `slo.restore.rto.kernel{档位}` |
| `REL-010` | 必须 | 因持久化层无压缩无轮转，必须为单会话事件数定义硬上界〔待压测回填〕，超限触发归档（合成快照或派生新会话） | 注入：向单会话写入超过上界的事件；观察：触发归档事件、恢复 RTO 仍落在档位目标内；无上界或无归档动作即失败 | §9.1、C21 | 域外会话索引的事件计数 + 归档触发器 |
| `REL-011` | 必须 | 「connector 重建 RTO」必须单独定义，测量点 = 恢复开始 → 必需 connector 就绪（工具可见），不得与内核日志恢复 RTO 合并 | 注入：断开必需 connector 上游后触发恢复；观察：两个 RTO 指标各自有样本，且 connector 就绪时刻晚于日志恢复完成时刻 | §9.1、§4.1.2、C16 | 指标 `slo.restore.rto.connector` |
| `REL-012` | 必须 | 「用户可见 RTO」必须有数字〔待压测回填〕，测量点 = 崩溃时刻 → 该会话再次接受 turn，且必须等于内核日志恢复 + connector 就绪之和（差额需解释） | 注入：单域崩溃；观察：`slo.restore.rto.user_visible` 有样本，且与两个分 span 之和的偏差 ≤ 10%（超差须给出未归因区间的 span 名） | §9.1、§9.5 | 指标 `slo.restore.rto.user_visible` |
| `REL-013` | 必须 | 「节点内 RPO = 0」的含义必须限定为「已 flush 位置之前无丢失」，排除项必须是「未 flush 的追加」，且必须单独暴露未 flush 追加量 | 注入：在 flush 前 SIGKILL；观察：`rpo.in_node` 仍为 0，而「未 flush 追加量 > 0」被单独上报（二者不得互相掩盖） | §7.6、§9.1、C21 | 本地 flush 水位 + 未 flush 尾部计数 |
| `REL-014` | 必须 | 「跨节点 RPO」必须定义为复制滞后，给 P99 目标〔待压测回填，设计文档以 30 s 为初值〕，测量点 = 本地上传尾部 seq 与上传确认水位 seq 之差换算时间 | 注入：节点故障后从对象存储恢复；观察：实测丢失区间 ≤ 该 P99 目标；报表中该字段不得为 0 | §7.6、§9.1、§9.5 | 指标 `rpo.cross_node{tenant}` |
| `REL-015` | 必须 | 「迁移成功率 ≥ 99.9%」分子 = 迁移完成且一致性断言（见 `REL-089`）通过的次数；分母 = 发起的迁移次数；运维主动取消单列并从分子分母同时扣除 | 注入：10 次迁移中人为使 1 次断言失败；观察：成功率 = 9/10 而非 10/10，且失败样本进入 `FAILED` 计数 | §9.1、§5.4.1 | 迁移状态机事件流 |
| `REL-016` | 必须 | 「无写者会话时长 P99 ≤ 5 min」测量点 = `HANDOFF_ARMED` → 目标域 `OWNED` 的区间；样本必须包含进入 `FAILED` 后重驱动的会话 | 注入：迁移 100 次并令其中 5 次进入 FAILED 后重驱动；观察：P99 ≤ 5 min，且失败样本在分布中可见（剔除失败样本即失败） | §5.4.1、§9.1、C23 | 迁移状态机时间戳 |
| `REL-017` | 必须 | 「审计落库时延 P95 ≤ 5 s」测量点 = 域内事件产生（域内时钟）→ 域外落库确认（域外时钟）；必须定义并登记**时钟偏差上界**〔待压测回填，且不得大于该 SLO 的 1/5〕 | 交付时钟偏差上界值与来源（NTP/chrony 实测）；注入：把域内时钟快 10 s；观察：该域样本被标记 `clock_skew_exceeded` 并单列，不静默计入时延 | §9.1、§4.2.1 | 域内事件时间戳 + 域外落库确认时间戳 |
| `REL-018` | 必须 | 「最小审计集可用性 99.99%」定义 = `1 − 因最小审计集写入失败而被拒绝的动作数 / 全部需要最小审计集的动作数`；最小集成员定义见 `SEC-069`，拒绝行为见 `SEC-070`（本规格只定义该指标的口径与分母） | 注入：最小审计集存储不可用；观察：需要最小集的动作被拒（比例 > 0），其余动作成功率不受影响；被拒比例进入该指标分母 | §2.4、§9.1、§9.2、`SEC-069`、`SEC-070` | 动作拒绝点 + 域外审计写入结果 |
| `REL-019` | 必须 | 「对账差异率 ≤ 0.01%」必须以金额为单位、窗口为 T+24 h 快照，且 `diff_under`（少计 / 收入漏损）与 `diff_over`（多计 / 客户争议）**分列**，不得合并为单一差异率 | 注入：构造 100 元少计与 100 元多计各一笔；观察：两列各显示 100 元、合并差异 = 0 而两列非零（合并即失败） | §7.6、§9.1 | 对账报表模板（分方向必填字段） |
| `REL-020` | 必须 | 「对账收敛时长 ≤ T_h」的 T_h 必须有数字〔待压测回填〕，测量点 = 差异首次被观测 → 连续两个窗口差值均为 0 | 注入：制造一笔 500 元少计；观察：从首次告警到两窗归零的时长 ≤ T_h，且期间该租户差异率曲线单调下降（回弹即失败） | §7.6、§9.1 | 指标 `recon.converge{tenant}` |
| `REL-021` | 必须 | 「挂死轮次」定义 = 无进展时长 > `T_turn` 的轮次数，无进展判定见 `REL-108`；必须按租户与按工具聚合暴露 | 注入：工具 promise 永不 resolve 且不遵守 `exec.signal`；观察：`turn.hung.count` +1，且该轮在 `T_turn` 后出现 `turn.cancelled{reason=deadline}` | §4.4.1、§9.1 | 域内轮次进展心跳 + 指标 `turn.hung.count` |
| `REL-022` | 必须 | 「MCP 工具可用率 ≥ 99%」必须**按时间**计算（工具可见状态时长 / 窗口总时长），不得按调用次数；排除项 = Registry 状态为「已下架」的 connector | 注入：某 connector 断开 151.5 s 后自动重载；观察：该窗口可用率下降 ≈ 重载时长占比；若按调用计数则断开期无调用会显示 100%（该算法即失败） | §9.1、C42 | Connector 控制器状态机时长累加 |
| `REL-023` | 必须 | 「重连耗尽 → 自动重载完成 P95 ≤ 60 s」测量点 = 域外观测到重连预算耗尽 → 工具恢复可见 | 注入：切断 connector 上游 ≥ 151.5 s；观察：从预算耗尽到工具可见的时长 P95 ≤ 60 s，且期间**摘域计数 = 0** | §4.8.3、C42、§9.1 | Connector 控制器重载 span + 工具可见性事件 |
| `REL-024` | 必须 | 端到端首 token SLO 的样本必须排除「会话冷启动后首个 turn」，该样本单列 `cold-first-turn` 指标 | 交付两套指标；若冷启动样本被并入端到端首 token，则与 `REL-008`/`REL-012` 的 RTO 档位互相矛盾（同一现象两个阈值） | §9.1、§7.4 | 指标分组（`warm` / `cold-first-turn`） |
| `REL-025` | 必须 | 已删除的错误指标不得复活：`toolAllowlist` 拒绝数不得存在（该路径按构造恒为 0），必须改为「白名单外**注册尝试**数」并作硬告警；不得出现同义反复的 RPO 表述（该事件的产生点见 `SEC-012`） | 检索指标登记表：出现 `toolAllowlistDenied` 即失败；`register.attempt_outside_allowlist.count` 必须存在且接入硬告警（见 `REL-124`） | §9.1（已删除项）、D10、D16、`SEC-012` | 指标登记表 CI 校验 |
| `REL-026` | 必须 | 每条 SLO 必须声明错误预算归属方（平台 / 模型 / 依赖）；模型责任失败不得消耗平台错误预算 | 注入：模型网关 100% 失败 30 min；观察：平台错误预算消耗 = 0，模型方预算按量消耗 | §9.1、G2 | 错误预算记账器（按归因分账） |
| `REL-027` | 必须 | 全部标注〔待压测回填〕的参数必须登记于《待回填参数台账》，含 {参数名, 用途, 影响的需求 ID, 回填阶段, 负责人, 回填方法}；未登记者视为「无来源数字」 | 全文检索〔待压测回填〕标记与台账逐项对齐，出现未登记项即失败；且台帐每项必须能在 P4 前给出实测值 | §14（未覆盖域补齐计划）、§12 P4 | 文档 CI 校验 + P4 回填评审 |

### 2.2 恢复路径的分 span 要求

| ID | 级别 | 条款 | 验收判据 | 依据 | 拦截点 / 测量点 |
|---|---|---|---|---|---|
| `REL-028` | 必须 | 恢复路径必须拆为五个 span 并各自埋点：`restore.acquire_lock`、`restore.read_and_closers`、`restore.fold`、`restore.connector_ready`、`restore.toolset_ready` | 任一次恢复必须在追踪中产生全部五个 span，缺失任一即失败；五个 span 起点终点必须可拼成不间断时间线，空隙之和 ≤ `REL-012` 目标的 5%（回填） | §9.1「RTO 的分 span 要求」、§7.4 | 域内恢复埋点 + 域外追踪采集 |
