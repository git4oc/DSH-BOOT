## 1. 角色职责与边界

### 1.1 本规格管什么

| # | 覆盖主题 | 主要依据 |

### 1.2 本规格不管什么

| 主题 | 归口 |
|---|---|
| SLO 数值、错误预算、降级阶梯 L0–L3/L1b 的阈值与滞回、故障域矩阵、恢复与迁移流程、容量与演练门禁 | `SPEC-02` |
| 代码结构、模块划分、契约测试套件、CI/CD 门禁、DevEx、仓库结构、反转面实现工作量 | `SPEC-03` |
| 用户可见文案、SKU 与隔离承诺的商业表述、定价与配额商业规则、UI 状态、上市判据 | `SPEC-04` |
| 版本与兼容面、格式版本演进、依赖生命周期与弃用、密钥与证书轮换流程、灾备拓扑与跨区切换 | `SPEC-05` |
| DSH 内核自身的功能开发；供应商选型（IdP、密钥库、云厂商） | 本规格集不覆盖（`SPEC-00` §1.3） |

**分工声明**：本规格对加密与驻留只写"**必须有**"（如 `SEC-101`、`SEC-102`），其密钥轮换流程、生命周期与灾备拓扑由 `SPEC-05` 承载；本规格对审计只写"**必须记什么、记不下怎么办、如何证明**"，其存储容量与吞吐参数由 `SPEC-02` 承载。

### 1.3 阅读约定

- 级别用语按 `SPEC-00` §3。
- 每条需求的末列为**拦截点**（preventive，动作不可能发生）或**测量点**（detective，只能发现动作发生过）。标 `detective` 者**不构成硬保证**。
- 跨规格引用只用 ID（`SPEC-00` §4.3）。

## 2. 规范性条款

### 2.1 威胁模型与 TCB

| ID | 级别 | 条款 | 验收判据 | 依据 | 拦截点 / 测量点 |
|---|---|---|---|---|---|
| `SEC-001` | 必须 | TCB 只允许包含"域镜像 + 只读 Profile + 域外全部组件"；域内运行期组件、域内上报、模型生成的动作与数据一律不得计入 TCB | 输入：对 Profile 生成物与安全设计清单做逐项核对。观察：被声明为 TCB 的条目全部落在"域镜像 / 只读 Profile / 域外组件"三类内；出现任一域内运行期组件（含 attest 上报、域内漂移上报、域内 schema 哈希）即判不通过 | `D2`、`D15` | 拦截点：域外 Profile 生成器的 TCB 清单校验（挂载期） |
| `SEC-002` | 不得 | 不得把"域内自证"（自报指纹、域内漂移上报、域内工具集自述）列入任何硬强制链 | 输入：检查强制链清单每行的"性质"列。观察：无任何 attest 或漂移项被标 preventive 或计入硬保证；存在即不通过 | `D15`、§5.3.1 | 拦截点：规格与设计评审（`GATE-002` 条件 1 的负向用例核对） |
| `SEC-003` | 必须 | 凡需硬保证的能力，必须落在三类拦截之一：① `ctx.tools.register` 唯一入口拦截；② 挂载前不插入插件行；③ 使能力不可达（预设表收敛）。声明式清单不得作为硬保证 | 输入：对每条标"硬"的控制列出其拦截点。观察：每条的拦截点属于三类之一且非空；出现以"域内只注册 X"式声明充当硬控制者，该条须降级为 `应当` 或删除 | `D16`、§4.5.1 | 拦截点：域外 Profile 生成器 + 规格评审 |
| `SEC-004` | 必须 | 每条约束必须归入且只归入硬 / 软 / 缓存一级；标"硬"的约束在依赖不可用时必须 fail-closed 拒绝该动作 | 输入：抽取约束清单，逐条与 §2.4 的三级定义比对。观察：无二义条目；对每条硬约束停掉其依赖后触发动作，动作被拒绝且无副作用 | `D12`、§2.4 | 拦截点：各硬动作的域外决策点（fail-closed 分支） |
| `SEC-005` | 必须 | 域内工具集必须等于 Profile 的 `toolAllowlist`，且必须含负向用例：受控恶意 MCP 推送新工具时，该工具永不进入模型可见集 | 输入：受控 MCP 服务器在运行期推送工具 `evil__pwn`。观察：`GET /v1/sessions/{id}/tools` 与模型请求的 tools 数组均不含该名，且最小审计集出现一条"白名单外注册尝试" | `D16`、`C35`、`GATE-002` 条件 1 | 拦截点：域内工具注册桥（`ctx.tools.register` 唯一入口） |
| `SEC-006` | 必须 | `toolAllowlist` 缺省语义必须是"无工具"，不得是"全部工具" | 输入：提交一份缺 `toolAllowlist` 字段的 Profile。观察：域外生成器拒绝签发，或域以空工具集启动；绝不出现非空工具集 | §6.2、`D16` | 拦截点：域外 Profile 生成器（schema 必填）+ 就绪判据 |
| `SEC-007` | 必须 | 域令牌必须绑定 `(tenantId, isolationGroupId)`，签发时固化；域外必须校验"请求中的租户 == 令牌中的租户" | 输入：用租户 A 的域令牌请求凭证代理并声称 `tenantId=B`。观察：返回拒绝且产生硬审计；以同租户身份重放同一请求正常通过 | §4.2.1、`C14`、`GATE-002` 条件 5 | 拦截点：反向网关、凭证代理、MCP 出站代理的入站校验（域外） |
| `SEC-008` | 必须 | 域到域外的凭证访问必须使用会话级租约，TTL ≤ 5 分钟，不得 per-request | 输入：抓取单会话一小时内域到凭证代理的请求序列。观察：租约签发次数远小于工具调用次数，单张租约 TTL ≤ 300 s，且不出现"每次调用一次取凭证" | §4.2.1 | 测量点：凭证代理签发表（计数与 TTL 分布） |
| `SEC-009` | 应当 | 应当定义域内时钟偏差上界；未定义时审计时延与租约 TTL 的判定标为不可判定 | 输入：采集域内与域外时间源偏差。观察：给出 P99 上界数字并登记；无数字时，相关测量点须标 `不可判定` | §4.2.1、§9.1 | 测量点：域内外时钟差监控（detective） |

### 2.2 强制链九项与拦截点

**索引**：§5.3.1 的九项依次对应 `SEC-010`（Profile 生成与层级校验）、`SEC-011`（制品完整性）、`SEC-012`（工具注册拦截）、`SEC-013`（插件行移除）、`SEC-014`（预设表收敛）、`SEC-015`（只读挂载）、`SEC-016`（就绪判据门禁）、`SEC-017`（域外 attest）、`SEC-018`（运行期漂移检测）。

| ID | 级别 | 条款 | 验收判据 | 依据 | 拦截点 / 测量点 |
|---|---|---|---|---|---|
| `SEC-010` | 必须 | Profile 生成与层级校验必须在域外完成；分层标记（平台锁定层 / 场景可选层 / 租户自定义层）的合法性判定不得在域内进行 | 输入：构造一份把租户自带 tool 插件标为 `tier: platform` 的 Profile。观察：域外生成器拒绝签发，域不得进入 ready，且产生审计记录 | §5.3.1-1、§5.3、`D9` | 拦截点：域外 Profile 生成器（preventive） |
| `SEC-011` | 必须 | 插件制品在加载前必须校验哈希与签名；校验失败必须拒绝加载该行并拒绝 ready | 输入：把某插件制品的字节改 1 byte（文件名与版本号不变）。观察：加载被拒、域不 ready、产生硬审计；哈希与签名均匹配时正常加载 | §5.3.1-2、§5.3 | 拦截点：域外加载器包装层（挂载前） |
| `SEC-012` | 必须 | 所有工具注册必须经域内工具注册桥的单一路径；桥必须对每次 `register()` 判定 `toolAllowlist` 成员资格，非成员一律不注册并记硬审计 | 输入：向域内注入一个直接调用 `ctx.tools.register('not-in-allowlist')` 的探针插件。观察：该工具不出现在模型可见集，且最小审计集产生"白名单外注册尝试"记录 | `C49`、`D16`、§5.3.1-3 | 拦截点：域内工具注册桥（唯一入口，**核心 preventive**） |
| `SEC-013` | 必须 | 挂载前必须移除 `tool-plugin-manager` 与 `plugin-manager` 两行，并关闭 `hmr`；只移除工具行不满足 | 输入：域启动后读取 Profile 的 `removedRows` 与 `hmr`，并枚举活动 fiber。观察：`removedRows` 同时含两行、`hmr.enabled=false`、无对应活动 fiber；缺任一即拒绝 ready | `C36`、§4.1、`GATE-002` 条件 3 | 拦截点：Profile 挂载前（不插入行）+ 就绪判据 3 |
| `SEC-014` | 必须 | Profile 必须只定义单一权限预设，使 `danger-full-access` 与 `never` 不可达 | 输入：枚举域内生效预设集合，并尝试切换到 `danger-full-access` 或 `never`。观察：生效集合等于单一预设，切换不可达；就绪判据 4 通过 | `C38`、§4.6 | 拦截点：域外 Profile 生成器 + 就绪判据 4（`SEC-040`） |
| `SEC-015` | 必须 | `cordis.patch.yml`、`package.json`、`compatibility.json` 与插件制品目录必须以只读方式挂载 | 输入：域内进程分别以写模式打开上述四类路径。观察：四次均失败（只读文件系统或权限拒绝），且就绪判据 6 通过 | §4.1、§5.3.1-6 | 拦截点：容器挂载层 + 就绪判据 6（`SEC-042`） |
| `SEC-016` | 必须 | 域就绪判据 7 条必须由域外 Session Router 判定；任一条失败即拒绝 ready，不得由域内自报通过 | 输入：分别构造 7 种失败态（见 `SEC-037`–`SEC-043`）。观察：每种都产出"拒绝 ready"且该域不接收任何会话 | §4.1.2、§5.3.1-7 | 拦截点：Session Router（域外门禁） |
| `SEC-017` | 必须 | 域外 attest 的用途限于"发现配置漂移"：接受域上报指纹并与域外已知摘要比对，不一致即告警；**不得**计入硬保证，也**不得**作为任何能力的唯一拦截 | 输入A：篡改域内某工具 schema 后触发 `boot` attest。观察：比对不一致，产生告警并进入重新签发或摘域流程。输入B：停掉 attest 服务。观察：工具面强制仍由 `SEC-012` 保证（负向用例仍不进入可见集） | `D15`、§5.3.1-8 | 测量点：域外 attest 服务（**detective**）；其失败可作为就绪门禁的拒绝依据，但不构成防篡改 |
| `SEC-018` | 必须 | 运行期漂移检测必须区分两类事件：connector 生命周期变化（预期，不摘域）与 Profile 未授权注册或工具出现（异常，摘域且摘域动作单独审批） | 输入A：触发 MCP 重连预算耗尽（约 151.5 s）。观察：该 connector 工具不可用 + 告警 + 自动重载，域不摘除。输入B：域内出现清单外注册尝试。观察：触发摘域流程，且该动作进入独立审批后才执行 | `C42`、§4.8.3、§9.2 | 拦截点：域外漂移判定 + 摘域审批（detective 触发 preventive 处置） |
| `SEC-019` | 必须 | 因内核无 pre-register 钩子、`register` 是唯一入口，桥必须覆盖全部注册调用点，含 MCP 发现循环、scoped 注册与运行期动态注册 | 输入：枚举代码树中全部 `ctx.tools.register` 调用点。观察：每处都经桥；构造一个绕过桥的 scoped 注册探针，该工具不进入模型可见集 | `C49`、`C19`、§11.1 | 拦截点：工具注册桥的装配层（对 `ctx.tools` seam 的整体反转） |

### 2.3 工具与插件面

| ID | 级别 | 条款 | 验收判据 | 依据 | 拦截点 / 测量点 |
|---|---|---|---|---|---|
| `SEC-020` | 必须 | MCP 收到 `notifications/tools/list_changed` 后自动重做发现所得的新工具，在域外对其重新授权之前不得进入模型可见集 | 输入：受控 MCP 服务器初始只暴露工具 `a`，稳定后新增 `b` 并发 `list_changed`。观察：60 s 内 `GET /v1/sessions/{id}/tools` 与模型 tools 数组均不含 `b`，最小审计集记录 rawName=`b` 的注册尝试；域外把 `b` 写入 `toolAllowlist` 并重签发 Profile 后 `b` 才出现 | `C35`、§4.5.1 拦截点 2、§5.6 | 拦截点：工具注册桥内的 MCP 发现闸门（同一入口） |
| `SEC-021` | 必须 | connector 工具数相对基线发生突变时，必须冻结该 connector 的新工具可见性并告警；冻结不得摘除整域，也不得影响该 connector 既有工具 | 输入：使某 connector 工具数由 5 变 6。观察：产生 `connector.state` 事件与告警，新增工具不可见，既有 5 个工具仍可调用，域未被摘除 | §5.6、§9.3 | 拦截点：Connector Registry 健康判定 + 注册桥闸门 |
| `SEC-022` | 必须 | 桥的成员资格判定依据必须只来自域外下发且只读挂载的 `toolAllowlist`；不得读取域内可变状态（环境变量、域内文件、域内注册表） | 输入：域内进程改写环境变量或域内配置文件，试图放行 `not-in-allowlist`。观察：该工具仍不注册，且产生硬审计 | `D9`、`D16` | 拦截点：工具注册桥（判定源为只读 Profile） |
| `SEC-023` | 必须 | Profile 必须定义 `sandboxModeCeiling`；模型对单次调用请求的更宽模式超过上限必须被拒绝，判定在域外完成 | 输入：`sandboxModeCeiling=read-only` 时，模型对一次写文件调用报 `sandbox_permissions=workspace-write`。观察：调用被拒、目标文件未创建、最小审计集含该请求与拒绝结论 | `C38`、§4.5.1 升权处置、§6.2 | 拦截点：域外策略与审批判定点（不依赖域内） |
| `SEC-024` | 必须 | 域外审批方必须解析该次调用的 `sandbox_permissions` 与 `justification`；解析不到即 fail-closed 拒绝，不得盲批 | 输入：构造一份缺失 `sandbox_permissions` 字段的审批上报。观察：审批收敛为 `rejected` 或 `unavailable`，工具未执行 | `C9`、§4.5.1 | 拦截点：域外审批服务（`/internal/kernel/approval/request`） |
| `SEC-025` | 必须 | 预设表只含单一预设，且部署环境变量 `DSH_PERMISSION_MODE` 恒为 `read-only`；不得设为 `danger-full-access` | 输入：读取域内生效预设集合与环境变量，并尝试经 Remote `permissionPresets.set()` 或环境变量切换。观察：生效集合等于单一预设，环境变量值为 `read-only`，切换请求被拒并进最小审计集 | `C38`、`C29`、§4.6 | 拦截点：域外 Profile 生成器 + 容器环境构造 + 就绪判据 4（`SEC-040`） |
| `SEC-026` | 必须 | 域内不得存在可触发会话级沙箱模式提升的写路径；显式模式只允许来自域外审批返回 | 输入：域内调用 `setSandboxMode` 或等价 seam 请求 `danger-full-access`。观察：会话日志中不产生 `sandbox/mode` 事件、生效模式不变、产生硬告警 | `C37`、§4.6 | 拦截点：Profile 装配层（不装配写路径）+ 域外模式真源（域外签发值优先于任何会话事件） |

> **本节为 `SPEC-00` `U-2` 的闭合新增。** 设计 §3.2 定义 `Skill Catalog` =「`SKILL.md` 资产的发布、分发、资源读取」，消费经 `ctx.skills` seam；但本规格此前的 104 条需求与其余四份规格**均未覆盖 Skill**，导致 `GET /v1/skills` 无需求归属。本节补齐资产的**安全语义**；其**分发实现**归 `SPEC-03` `ENG-063`。

| ID | 级别 | 条款 | 验收判据 | 依据 | 拦截点 / 测量点 |

| `SEC-105` | 必须 | Skill 资产**必须**按三级作用域隔离：`platform`（全租户共享）/ `tenant`（该租户）/ `user`（个人）。域内**不得**跨作用域读取——一个 `user` 级 Skill **不得**出现在其他用户的可见集中，`tenant` 级**不得**跨租户可见 | ① 构造同租户两个用户各持一个 `user` 级 Skill：断言 A 的会话可见集中不含 B 的 Skill（双向）；② 构造两个租户各持 `tenant` 级 Skill：断言互不可见；③ 域内 skills 服务的可见集**必须**等于 Profile 声明根集合的并集，**不得**由域内自行扩展 | §3.2 Skill Catalog、§4.2 `ctx.skills`；`C26` 同类风险（seam 无调用方授权 ⇒ 不得直通） | preventive：域外 Profile 决定挂哪些根；域内 provider 只装配 |
