## 1. 角色职责与边界

### 1.1 本规格管什么

本规格规定**怎么做成**，不含**为什么这样设计**。覆盖范围：

1. **反转面契约**（设计 §4.2）：`ctx.llm` / 工具注册桥 / `ctx.approval` / `SessionPersistence` 四个面的接口签名、责任边界、错误语义，以及"每一面可独立开发与独立测试"的可验证化要求。
2. **模块划分与仓库结构**：包划分、层间依赖方向、禁止的反向依赖。
3. **版本列车纪律**（`C33` / `C34`）：`trainVersion` 单值、混版检测、"存在 `disabled` 关键行 → 域不得 ready"的实现落点、Profile 校验、必需插件断言。
4. **契约测试与升级门禁**（`C41`、设计 §11.4）：发行版**没有**契约测试套件 ⇒ 自建套件的必测项、内核 `.d.ts` API 快照 diff 机制、`GATE-006`。
5. **P1 分层**（设计 §11.4.1）：L1 / L2 的范围与禁止事项、提供方重写规矩、镜像基线与域启动自检。
6. **DevEx**（`GATE-001`）：本地最小拓扑、反向网关桩、内存 attest、开发态 `toolAllowlist` 逃生门、测试夹具与故障注入器。
7. **CI/CD 门禁**：需求 ID 正则校验、契约测试、快照 diff、规格与代码一致性检查。
8. **实现顺序与依赖**：双轨排期、P-1 前置、可砍项。
9. **工作量量级**：按阶段的人月区间与团队规模（**标注为估算**，`SPEC-00` §1.3 已声明正式排期不属规格集）。

**排他声明**：本规格**不复制**上述任何正文。凡本规格出现"域外审批""最小审计集""fail-closed""SLO"等词，均为**引用性使用**，其判定标准一律以上表归口规格为准（`SPEC-00` `GATE-009`）。

## 7. 本角色无法覆盖的部分

1. **安全定性与合规义务的最终判据**：桥的拦截点、attest、审计最小集、凭证例外、Windows 披露文本的**安全强度与合规结论**不在本规格判定。本规格只保证"有拦截点、有审计、有自检、可验收"这一**工程形态**；其是否足以构成硬控制，由 `SPEC-01` 裁定（`D15`/`D16`）。
2. **SLO 数值、测量点、分母、错误预算与降级阶梯**：`T_a`/`T_m`/`T_turn` 的**取值合理性**、L1b 的有界丢弃阈值、缓冲容量口径、演练门禁的 6 项通过标准，均由 `SPEC-02` 归口。本规格只实现其配置通道与计时器。
3. **用户契约、商业条款与上市判据**：计费与配额口径、SKU 隔离承诺、删除承诺与撤销窗口、UI 状态、可砍项对客户的可接受性，由 `SPEC-04` 归口。本规格只提供开关与校验器。
4. **兼容面清单与弃用流程**：哪些工具名、preset id、事件字段属于永久兼容面，以及弃用通知期与迁移路径，由 `SPEC-05` 归口。本规格的快照机制只**检测变化**，不判定"是否允许变化"。
5. **DSH 内核自身的缺陷与功能缺口**：`C41`（发行版无契约测试套件）、`C34`（混版静默 `disabled`）、`C23`（`session.lock` 无过期）、`C24`（无删除接口）、`C25`（`invariants` 需显式挂载）都是**外部事实**；本规格以自建套件、就绪判据、分层与启动自检**绕行**，不覆盖内核修复。
6. **正式排期与人力编制**：`ENG-058` 是**估算输入**，不构成承诺；编制、招聘与发布日历不属规格集（`SPEC-00` §1.3）。
7. **容器/microVM 平台行为**：Windows 容器内 ACL 的实测结论、`session.lock` 在具体存储介质（SMB / 对象存储 FUSE / NFS 变体）上的可靠性，属环境验证项；本规格只要求"镜像基线断言"与"启动自检"，实测结论未闭合前 Windows 不得参与多租户隔离（`GATE-002` 条件 7，归 `SPEC-01`）。
