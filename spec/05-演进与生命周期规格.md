# 演进与生命周期规格

| 项 | 值 |
|---|---|
| 文档编号 | `SPEC-05` |
| 版本 | 1.0 |
| 状态 | 生效 |
| 角色 | 演进 / 反脆弱架构师 |
| 上游依据 | 设计文档 v2.6；`SPEC-00` v1.1 |
| 写作用域 | `spec/05-演进与生命周期规格.md`（排他） |

> 本规格的主题是**变化**：系统在时间维度上的正确性。
> **稳态由其他规格负责**——本规格不重复描述任何稳态机制，只规定"发生变化时系统必须如何表现"。
> 一句话立场：**任何变化都必须可被检测、可被处置、可被回退；不可回退的变化必须被显式承认并写进备份与合同。**

## 1. 角色职责与边界

### 1.1 本规格管什么

| # | 覆盖域 | 对应章节 |
|---|---|---|
| 1 | **版本与列车纪律**：`trainVersion` 单值、整列同升、禁止混版、按域批次灰度、混版检测与拒绝就绪 | §2.1 |
| 2 | **格式版本边界**（C39）：域冻结在 format 版本、跨格式版本不可接收迁移会话与快照、"保留旧域"不是回滚方案、备份的格式耦合 | §2.2 |
| 3 | **永久兼容面**（§10.2）：preset id 只增不删、preset 三处持久痕迹、会话创建后 preset 不可变、工具名不得静默改名、平台级 preset 解析不变量 | §2.3 |
| 4 | **依赖生命周期**：connector 下架后的退化、工具从 `toolAllowlist` 消失时审批规则的处置、模型降级策略的**定义义务**、模型多供应商抽象 | §2.4 |
| 5 | **弃用流程**：内核弃用端点/语义时的兼容垫片与移除排期 | §2.5 |
| 6 | **事件映射的稳定性**：§6.4 产品事件 ⇄ DSH 事件映射作为兼容面；事件语义变更规则；SSE 缺口语义 | §2.6 |
| 7 | **灾备、加密与数据驻留**：区域绑定、跨 AZ 是"恢复"不是"重调度"、行级 RTO/RPO 补全、驻留证明 | §2.7 |
| 8 | **变化场景的可接受性**：内核大版本升级、单租户 100x、依赖供应商弃用、某租户域失陷、监管变化 | §2.8 |

**判据归口**：本规格写**规则与判据**（什么可接受、什么必须拒绝、在哪儿被拒）；**实现机制**由 `SPEC-03` 负责。凡本规格出现"拦截点"，指的是该约束被强制或被测的**位置**，其实现形态与工程落地见 `SPEC-03`。

### 1.2 本规格不管什么（明确指向其他 SPEC）

| 项 | 归属 |
|---|---|
| 安全语义、TCB 与信任模型、强制链、凭证与密钥的**安全口径**、审计取证、DSR 流程本身、披露义务 | `SPEC-01`（`SEC-###`） |
| SLO 数值与测量、降级级别 L0–L3/L1b 的定义、故障域矩阵的**数值**、恢复与迁移的**运行时机制**、演练门禁的判定 | `SPEC-02`（`REL-###`） |
| 代码结构与模块划分、升级流水线/CI 门禁的**实现**、契约测试套件的**实现**、DevEx、仓库结构 | `SPEC-03`（`ENG-###`） |
| 用户契约、SKU 与隔离承诺、计费与配额、删除承诺的**对外表述**、UI 状态、上市判据 | `SPEC-04`（`PRD-###`） |

**边界规则**：本规格**不写**"如何实现"，也**不写**"数值目标"。本规格写的是：**变化发生时，哪些状态不可接受、哪些动作必须被拒绝、哪些证明必须存在**。
**同时禁止**（`GATE-009`）：本规格**不得**对上述四域各写一份正文；出现冲突时按 `SPEC-00` §1.2 的权威顺序提给总纲维护者裁定。
