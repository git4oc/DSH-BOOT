## 1. Profile 字段对齐（不得另立一套）

| Profile 字段 | 类型 / 约束 | 语义 | 本文件如何使用 |
|---|---|---|---|
| `buffers.audit` | object，必填 | 审计缓冲配置 | 读 `retainHours` 作为**时间容量** |
| `buffers.billing` | object，必填 | 计费缓冲配置 | 同上 |
| `buffers.<kind>.retainHours` | integer，`≥ 1`，`bufferConfig` **仅允许该字段** | 按**时间**定容量（不是字节数） | 进入 / 退出 L1b 的主阈值；`retainHours ≥ 24`（设计既定） |

> `bufferConfig` 为 `additionalProperties: false` ⇒ 字节安全阀、抖动上界、令牌桶速率**不得**写入 Profile。其落点为**平台配置中心按 `kind` 分键**（`buffer.byteValve.{kind}`、`resend.jitterBound`、`resend.tokenBucketRate`），域外下发时必须校验 §2.2 的换算关系。

## 2. 双缓冲参数（`REL-052` / `REL-053`）

### 2.1 独立判定（一个缓冲进入 L1b 不得触发另一个进入任何级别）

| 维度 | `kind = audit` | `kind = billing` | 独立性校验 |
|---|---|---|---|
| 水位 | `buffer.level.audit` | `buffer.level.billing` | 两条曲线独立采集，不得复用同一序列 |
| 时间容量 | `retainHours`（audit） | `retainHours`（billing） | 两个 Profile 子对象分别读取 |
| 字节安全阀 | `PP-28{kind=audit}` | `PP-28{kind=billing}` | 平台配置分键 |
| 丢弃计数 | `buffer.discard.count{audit}` | `buffer.discard.count{billing}` | 两个计数器 |
| L1b 判定器 | 独立实例 / 独立状态 | 独立实例 / 独立状态 | 级别事件必须携带 `subKey`（`REL-DOC-04` §1.2） |
| 告警 | 独立阈值、独立去抖 | 同左 | 告警载荷含 `kind` |
| **注入判据** | 使审计缓冲进入 L1b：计费缓冲水位与丢弃计数**必须不变**；计费维度出现降级事件即失败 | — | 缓冲实例隔离校验（配置 + 运行期维度级别比对） |

### 2.2 时间定容与字节安全阀

| 项 | 规则 | 推导 / 判据 |
|---|---|---|
| 时间容量 | `retainHours ≥ 24 h @ P99 事件速率` | 设计既定 24 h；`P99 事件速率 = PP-31{kind}` |
| 触发条件 | `oldestEventAge ≥ retainHours` **或** `bytes ≥ PP-28{kind}`，**先到者触发** | `REL-053` |
| 字节阀换算约束 | `PP-28{kind} ≥ PP-31{kind} × retainHours × B_event`（`B_event` = 单事件字节上界） | 保证字节阀的**换算时间容量 ≥ retainHours**；不满足即配置校验失败 |
| 容量换算示例（**示例值**，实际取 `PP-31`/`PP-28`） | `PP-31 = 200 事件/s`、`retainHours = 24`、`B_event = 2 KiB` ⇒ 字节阀下界 = `200 × 86,400 × 2 KiB ≈ 33.0 GiB` | 数值推导，非承诺值 |
| 不阻断 | 超限处置为有界丢弃 + 墓碑 + 硬告警，**不拒绝新 turn** | `REL-053`、`REL-059` |
| 验收注入 | 以 P99 速率匀速注入 24 h：丢弃计数 = 0；第 24–25 h 触发 L1b 且新 turn 受理率 100% | `REL-053` 判据 |

### 2.3 水位与阈值线

| 阈值 | 取值 | 触发动作 |
|---|---|---|
| 预警线 | 容量的 **50%** | 预警（不改变级别） |
| 告警线 | 容量的 **80%** | 告警（不改变级别） |
| L1b 进入线 | 容量的 **100%**（时间或字节先到者） | 进入 L1b：有界丢弃 + 墓碑 + **硬告警** |
| L1b 退出线 | 容量的 **50%** 且稳定 **5 min** | 退出 L1b（滞回：退出阈值严于进入阈值） |

> 50% 的推导：补传限速为到达速率的 2× 时，净排空速率 = `2 × arrival − arrival = arrival`；故最老事件年龄在 50% 处是**最后一个可收敛点**，低于此点积压仍能在容量耗尽前回落（`REL-054`）。

## 3. 补传参数（`REL-055`）

| 项 | 规则 | 参数 |
|---|---|---|
| 抖动 | 补传必须按**域**随机抖动（不是按事件、不是全局同步） | `PP-13`（上界） |
| 抖动下界约束 | `PP-13 ≥ PP-25`（上传间隔），保证同一域相邻两批不重叠 | 配置校验 |
| 令牌桶 | 域外上传入口按令牌桶限速；总速率与每域配额分别配置 | `PP-14`（总速率 + 每域配额） |
| 禁止 | 不得全 fleet 同刻补传 | 注入判据 |
| 注入用例 | 同时释放 100 个域的积压缓冲：域外上传 QPS 峰值 ≤ 令牌桶总速率；同刻峰值 > 总速率即失败 | 用例 `DRL-E18` |
| 与 SLO | 上传间隔分布 `SLO-23`；跨节点 RPO `SLO-09` | `REL-DOC-01` §2 |

## 4. 领先指标（`REL-054`）

| 指标 | 口径 | 采集点 | 与水位的关系 |
|---|---|---|---|
| `buffer.oldest_event_age.seconds{kind}` | 最老未上传事件的年龄（秒） | 缓冲实例（按 `kind` 分列） | **领先指标**；水位是滞后指标，**不得**以水位替代 |
| `buffer.level{kind}` | 水位（字符 / 百分比） | 同上 | 滞后指标，仅作对照 |
| `buffer.discard.count{kind}` | 有界丢弃事件数 | 丢弃点 | 必须等于墓碑数（§5.2） |

判据：以 P99 速率注入且补传限速为 2× 到达速率时，必须在 **50%** 处预警，且积压在容量耗尽前回落。

## 5. 墓碑 schema（`REL-056` / `REL-057`）

### 5.1 字段

| 字段 | 类型 | 必填 | 来源 | 用途 |
|---|---|---|---|---|
| `tombstoneId` | string（ULID） | 是 | 丢弃点生成 | 主键 |
| `tenantId` | string | 是 | 域令牌绑定值 | 对账分租户 |
| `isolationGroupId` | string | 是 | 域令牌绑定值 | 与审计键一致 |
| `workspaceId` | string | 是 | 事件上下文 | 用量归集 |
| `sessionId` | string | 是 | 事件上下文 | 检索 |
| `turnId` | string | 是 | 事件上下文 | **按 `turnId` 对账检索**（`REL-056`） |
| `eventType` | enum `billing` / `audit` + 子类型 | 是 | 缓冲 `kind` 与被丢弃事件类型 | 分列统计 |
| `discardAmountEstimate` | object `{unit, value}` | 是 | 丢弃时刻的估算（`unit ∈ {tokens, toolCalls, bytes}` 及折算金额） | 不可计费用量聚合（§5.3） |
| `discardedAt` | 单调时间戳 + 墙钟 | 是 | 丢弃时刻 | 时序与审计 |
| `reconciled` | boolean，固定 `false` | 是 | 丢弃即置 | 用量导出标记（`PRD-036`） |
| `dedupKey` | string = `hash(tenantId, turnId, eventType, bucketStart)` | 是 | 计算得出 | 重放去重（`REL-100` 同口径） |
| `reason` | enum `time_capacity` / `byte_valve` | 是 | 触发源 | 定位容量配置 |

### 5.2 一致性校验

| 校验 | 判定式 | 失败后果 |
|---|---|---|
| 计数一致 | `buffer.discard.count{kind} == count(tombstones{kind})` | 不等即失败（`REL-056`） |
| 可检索 | 每笔丢弃可按 `turnId` 在对账报表中检索到 | 检索不到即失败 |
| 可导出 | 用量导出中标为 `reconciled:false`（`PRD-036`） | 缺标记即失败 |
| 幂等 | 同一 `dedupKey` 重复写入只保留一条，去重计数 +1 | 重复计入即失败 |
| 硬告警 | 墓碑产生必须触发硬告警（不得降级为通知，`REL-124`） | 级别错误即失败 |

### 5.3 不可计费用量登记（`REL-057`）

| 项 | 内容 |
|---|---|
| 指标 | `usage.unmetered.cumulative`（累计不可计费用量，金额单位） |
| 聚合式 | `Σ over tombstones(discardAmountEstimate.value × 单价)`，按 `tenantId` 与 `window` 聚合 |
| 上限 | `PP-15`（累计上限，金额）；达到上限后**仍然不阻断执行**，必须告警并通知租户 |
| 合同口径 | 「已度量、有上限」的风险表述归属 `PRD-034`；L1b 客户可见文案归属 `PRD-037` |
| 注入判据 | 制造 3 次 L1b 丢弃：累计指标上升且有上限值；无上限或无累计值即失败 |

## 6. 温 / 零态冻结前置（`REL-058`）

| 序 | 动作 | 判定 | 失败后果 |
|---|---|---|---|
| 1 | `flush`（提交屏障） | 持久层返回成功 | 未 flush 即冻结 ⇒ 事件丢失（差异率超 0.01%） |
| 2 | 排空缓冲 | `oldest_event_age{kind} == 0` 且水位 = 0 | 未排空即冻结 ⇒ 缓冲内容丢失 |
| 3 | 写 `suspend` 标记 | 标记落库且可被恢复流程读取 | 缺标记 ⇒ 恢复流程状态不明 |
| 4 | 快照内容 | **必须**同时包含**投影缓存**与**未上传缓冲** | 缺任一 ⇒ 恢复后用量永久丢失 |

校验：构造「缓冲非空 + 有未上传事件」的域，冻结后恢复，事件数与用量差异率 ≤ 0.01%；缺任一前置动作即失败。顺序**不得**变更（1 → 2 → 3 → 4）。

## 7. 不得阻断执行（`REL-059`）

| 校验 | 判据 | 拦截点 |
|---|---|---|
| 拒绝原因码白名单 | 轮次拒绝原因码集合中**不得**存在任何软依赖取值（计费 / 一般审计 / 配额账本 / 会话索引 / 用量派生视图 / 缓冲状态） | 静态校验 + 代码审查 |
| 受理率 | 软依赖逐项停机 6 h **且缓冲打满**：新 turn 受理率 = 100% | 演练 `DRL-E22` |
| 轮次成功率 | 不得因软依赖不可用而变化 | 同上 |
| L3 计数 | = 0（软依赖不得实现为 L3） | `REL-DOC-04` §3.3 校验 |
| 并发 | 不得因缓冲水位降低并发 | 并发指标对照 |
