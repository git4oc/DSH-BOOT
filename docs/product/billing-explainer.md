## 1. 计费真源（对客可引用）

| 角色 | 存储 | 性质 |
|---|---|---|
| **唯一真源** | **会话事件日志 + 上传确认水位** | 追加型；水位界定"哪些已离开节点" |
| 派生视图 | 配额账本、计费、审计补写、会话索引 | **可重建**，允许落后 |

| # | 对客声明（逐字，本基线首次拟定） |
|---|---|
| 1 | 「计费真源为会话事件日志与上传确认水位；配额账本、计费视图与会话索引均为可重建的派生视图，允许短暂落后。」 |
| 2 | 「派生视图落后不影响你的会话执行。」（对应"软依赖不阻断执行"） |
| 3 | 「对账以真源裁定，差异回写派生视图。」 |
| 4 | 上述三项的**技术口径与验收**引用 `SPEC-02`：真源定义 `REL-090`、上传确认水位域外驱动与单调性 `REL-091`、裁定回写幂等 `REL-097`。 |

## 2. 幂等键与归因

| 项 | 规定 |
|---|---|
| 幂等键 | **`(tenantId, turnId)`**；派生视图按该键去重，重复上传不重复计费 |
| 归集粒度 | 按租户归集到 `turnId` |
| 令牌分列 | **输入 / 输出 / 缓存命中**三者分列计价 |
| MCP 归因 | MCP 调用**按 connector 归集** |
| 其余维度 | `dim` 取值为 `workspace` / `user` / `scenario` / `connector` |

**对客句（逐字）**：

```
用量按租户归集到每一个轮次（turnId），并以 (tenantId, turnId) 去重；输入令牌、输出令牌与缓存命中分别计价；MCP 调用按 connector 归集。
```

## 3. 对账窗口、新鲜度与差异披露

| 项 | 值 / 规定 |
|---|---|
| 对账窗口 | **T + 24 h**（快照式对账） |
| 数据新鲜度 | `GET /v1/usage` 对外声明为 **T+1** |
| 差异率目标 | ≤ **0.01%**（单位 = 金额），**少计与多计分列**；口径见 `REL-019` |
| 差异方向披露 | **少计（收入漏损）与多计（客户争议）方向相反，必须分列**；客户**可下载**分方向差异（少计、多计各一行金额） |
| 收敛时长 | **≤ `T_h`**；`T_h` 由 `SPEC-02` 的 `REL-020` 规定（该条要求 `T_h` 必须有数字〔待压测回填〕），本文件不另写数值 |
| 差异绝对上限 | 每租户 ≤ **X 元**（**待定**，由 `SPEC-02`（`REL-095`）与财务定） |
| 分列与报表 | 分方向字段 `diff_under` / `diff_over` 与"未上传尾部量"同窗展示，见 `REL-095`、`REL-096`；对账报表模板见 `REL-090`–`REL-101` |
| 裁定 | 差异以真源裁定并回写 |

**对客句（逐字）**：

```
对账窗口为 T+24 小时；少计与多计分别披露，你可以下载两个方向的差异金额。收敛时长目标见 SLA 所引用的可靠性条目。
```

## 4. 未对账标记与 L1b 表现

| # | 规定 |
|---|---|
| 1 | 计费与审计**各自独立缓冲**；超限时**有界丢弃**并以 **`reconciled:false` 墓碑**标记，**恢复后对账**；**不阻断执行**（不因计量问题拒绝新轮次）。 |
| 2 | 导出数据**必须**含「已对账 / 未对账（`reconciled:false`）」标记；存在不可计量窗口时，对应行标记为未对账，**不得**复用已对账数值。 |
| 3 | L1b（缓冲耗尽）发生时**必须**在同一窗口内显示逐字文案 `COPY-009`： |

```
部分用量未能计量，将于恢复后对账。你可以在用量页面看到受影响区间；若恢复后仍无法计量，将按你侧可核验的用量记录封顶结算。
```

| # | 规定 |
|---|---|
| 4 | 用量页**必须**标出**受影响区间的时间范围** |
| 5 | 文案**不得**承诺"不会多计费""不影响账单" |
| 6 | 不可计费用量作为**已度量且有上限**的风险写入合同：以「单月不可计量用量不超过承诺额度的 {X}%」形式表述；`{X}` **待定**（定价决策层 + `SPEC-02`） |

## 5. 限额、限速与连坐（对客承诺）

| 场景 | 对客表现 | 引用 |
|---|---|---|
| 配额达 **70%** | 提示（`应当` 级） | `PRD-035` |
| 配额达 **80%** | 控制台与会话页同时预警 + **自助扩容**入口；扩容即时生效，**不依赖人工工单** | `PRD-035` |
| 超出承诺额度 | 对**超额租户**按比例限速/排队；逐字文案 `COPY-010`：「你的用量已超过承诺额度，平台正在对本租户限速；其他租户不受影响。可自助扩容或等待下个计费周期恢复。」 | `PRD-039` |
| 公平性 | **不得**把某租户的用量失控转化为**其他租户**的不可用；**不得**对所有租户平等返回 503 | `PRD-038` |
| 同租户内 | workspace 并发与 CPU 份额为**硬约束**；某 workspace 超限只拒绝该 workspace 新轮次，同租户其他 workspace 不受影响 | `PRD-040` |
| 结算上限 | 超出上限后**只限速**，**不停止服务**、**不波及其他租户** | `PRD-034` |

## 6. 自助导出（客户独立复核账单）

| 项 | 规定 |
|---|---|
| 端点 | `GET /v1/usage/export`（CSV / JSON） |
| 粒度 | 按 `turnId` |
| 必含字段 | `turnId`、租户、workspace、user、scenario、connector、输入令牌、输出令牌、缓存命中、计价金额、**`reconciled`（已对账 / 未对账）**、事件时间、上传水位 |
| MCP | 按 connector 归集的调用量 |
| 客户复算 | 客户可用该导出**独立复算月账单**，差异可定位到具体 `turnId` |
| 能力写入材料 | 导出能力**必须**写入报价材料（`PRD-DOC-06` §3） |

**对客句（逐字）**：

```
你可以导出全量原始用量数据（按 turnId 粒度，含输入/输出令牌与缓存命中分列、MCP 按 connector 归集），用于独立复核账单，并把差异定位到具体轮次。
```

## 8. 计费 FAQ（对客）

| # | 问题 | 回答 |
|---|---|---|
| 1 | 账单和我自己的统计不一致怎么办？ | 以真源（会话事件日志 + 上传确认水位）裁定；下载分方向差异与 `turnId` 级导出，可定位到具体轮次。 |
| 2 | 为什么用量页面数据是 T+1？ | 用量视图为派生视图，对外声明新鲜度为 **T+1**；对账窗口为 **T+24 h**。 |
| 3 | 标了「未对账」的行怎么结算？ | 该区间恢复后对账；若恢复后仍无法计量，按你侧可核验的用量记录**封顶结算**。 |
| 4 | 超了额度会停机吗？ | 不会。超出上限后**只对超额租户按比例限速**，不停止服务、不波及其他租户；可自助扩容。 |
| 5 | 会不会因为别的租户用量大而影响我？ | 不会。平台不会把某租户的用量失控转化为其他租户的不可用。 |
| 6 | 同一个工作区里我同事把并发打满，我会受影响吗？ | 不会。workspace 级并发与 CPU 份额为硬约束，只拒绝该 workspace 的新轮次。 |
| 7 | 重复上传会不会重复计费？ | 不会。计费按 `(tenantId, turnId)` 幂等去重。 |
| 8 | 缓存的令牌怎么算？ | 输入、输出、缓存命中**分别计价**；缓存命中单价与输入/输出不同。 |
