## 1. TCB 组成（唯一合法三类）

**判定标准**：一个条目属 TCB，当且仅当它落在下表「类别」列的三值之内。任何条目被声明为 TCB 但不属三值之一 ⇒ 不通过（`SEC-001`）。

| 类别 | 条目（清单是封闭的；新增条目走 §6 变更流程） | 固定手段（使其可核验） |
|---|---|---|
| **A. 域镜像** | A1 基础镜像（`os` + 运行时 + 内核包 `@deepseek-ai/dsh-*` / `@deepseek-ai/cordis` 整列车）<br>A2 平台自研包（`@dsh-boot/domain-bridge`、`@dsh-boot/session-persistence-*`）<br>A3 插件制品目录（按 `integrity: sha512-…` 固定）<br>A4 容器运行时声明（挂载表、特权位、用户/命名空间、网络策略）<br>A5 `criticalRows` 常量清单<br>A6 域内装配的唯一输入——只读 Profile（见 B） | 镜像摘要、制品摘要、运行时配置快照 |
| **B. 只读 Profile** | B1 `profile.json`（域外生成器签发）<br>B2 `cordis.patch.yml`、`package.json`、`compatibility.json`<br>B3 插件制品目录（只读挂载点）<br>B4 Profile 生成摘要 `profileGenerationDigest` | 挂载内容摘要 `mountDigest` + 生成摘要 |
| **C. 域外全部组件** | C1 Profile 生成器；C2 Session Router（就绪判定/迁移/自建会话索引）；C3 反向网关；C4 凭证代理；C5 MCP 出站代理（含 stdio 宿主）；C6 attest 服务；C7 审计 WORM + 签名密钥；C8 KMS/HSM/密钥库；C9 保留与删除服务；C10 历史查询服务；C11 Connector Registry / 控制器；C12 OpenAPI 网关与身份/RBAC；C13 域池编排器 | 组件自身配置与自身日志（非域内上报） |

### 1.1 明确不属于 TCB 的条目（**不得**被任何硬保证引用）

| 条目 | 定性 | 允许用途 | 禁止用途 |
|---|---|---|---|
| 域内运行期组合（活动 fiber、运行期加载顺序） | 非 TCB（是 A 的**运行结果**，非裁决者） | 作为 A 类固定内容的交叉核验输入 | 作为 ready 通过依据、作为拦截点 |
| `/internal/kernel/attest` 域上报的指纹、工具 schema 哈希 | **detective**（`SEC-017`） | 发现配置漂移、触发调查/重签发 | 计入硬保证、作为任何能力的唯一拦截 |
| 域内漂移上报 | **detective**（`SEC-018`） | 触发摘域流程（摘域动作单独审批） | 作为 preventive 处置的依据 |
| 域内工具集自述（`GET /v1/sessions/{id}/tools` 的域内侧结果） | 非 TCB | 与域外判定清单做交叉核验 | 替代域外判定清单（`GATE-002` 条件 1） |
| 域内 schema 哈希、域内 selfcheck 输出、域内 `enforcement` 自报 | 非 TCB | 交叉核验、告警 | 作为门禁通过依据（`SEC-044`） |
| 模型生成的动作与数据 | **不可信执行域**（`D2`） | 一律视为对抗输入 | — |
| 会话日志中的域内事件（不含最小审计集） | 非 TCB 证据 | 恢复、折叠历史 | 作为安全事件唯一证据（`SEC-071`） |

### 1.2 桥这一处的定性（易被写错，单列）

| 对象 | 定性 | 依据 |
|---|---|---|
| `@dsh-boot/domain-bridge` 的**代码与制品** | **TCB**——它是 A2 的一部分，由镜像摘要与 `integrity` 固定 | `SEC-001`、`SEC-019` |
| 桥在运行期**自报**的断言（`bridge.installed`、`bridge.guard.installed`、自测端点输出） | **非 TCB / detective**——属"域内自报"，只作交叉核验 | `SEC-001`、`SEC-002`、`SEC-017` |
| 「白名单外工具不可达」的实际保证 | 来自**注册入口拦截**（域外清单驱动）；`guard` 仅兜底 | `SEC-029`、`VER-001` §3.4 |
| 端点 `/internal/kernel/ready/bridge` 的返回值（若实现） | **不得**单独决定 ready；必须与域外判定并列且以域外为准 | `SEC-044`、`SEC-DOC-04` §2 |

## 2. 每类资产的信任假设

**判定标准**：下表每一行给出「假设被推翻时可检出的域外事实」。检出手段一列为空的行 ⇒ 该资产**不得**被任何 preventive 条款引用。

| # | 资产 | 存放/持有 | 谁可写 | 信任假设（成立才可用） | 若推翻的后果 | 检出的域外事实（必填） |
|---|---|---|---|---|---|---|
| 1 | 域镜像 | 镜像仓库 | 仅平台发布流水线（域外） | 发布后字节不变；域内不可改 | 全部 preventive 判据失效（前提 `P-2`） | 镜像摘要（发布时登记）≠ 运行时实际拉取摘要 |
| 2 | 只读 Profile | 只读挂载（B1–B3） | 仅 Profile 生成器（域外） | 挂载后域内不可写 | 工具面/权限面可被域内改写 | `mountDigest`（挂载内容摘要）与生成摘要比对 |
| 3 | 插件制品 | 只读目录 | 仅发布流水线 | `integrity` 与签名在加载前校验通过 | 供应链投毒 | 制品摘要 + 签名校验结果（域外加载器） |
| 4 | 域令牌 | 域内进程内存 | 域外身份服务签发 | 绑定 `(tenantId, isolationGroupId)`，TTL ≤ 300 s | 域冒充他租户 | 域外入站校验日志（请求租户 ≠ 令牌租户即拒绝） |
| 5 | 会话租约（域→域外） | 域内进程内存 | 域外网关签发 | 会话级、非 per-request、TTL ≤ 300 s | 凭证面被高频放大 | 签发计数与 TTL 分布（域外表） |
| 6 | 凭证值 | 域外密钥库 | 域外 | **永不进入域内**（唯一例外见 `SEC-051`） | 凭证泄露 | 域外密钥库访问审计 + 域内 secret 形态扫描（detective 补充） |
| 7 | 会话事件日志 | 域卷 + 对象存储 | 域内写句柄（单写者） | 追加型、非安全证据源 | 对账被误导 | 上传确认水位 + 域外日志副本 |
| 8 | workspace 文件 | 域卷 | 该域（唯一写者） | 跨租户不可见；**域内读不隔离** | 同租户内越权读 | 域卷挂载归属（域外）+ 披露 `SEC-089` |
| 9 | 附件 / spill / FTS 派生库 | `<DSH_HOME>` 域卷 | 域内 | 随域销毁；不跨域 | DSR 漏删、数据副本外溢 | 域卷清单 + 文件存在性断言（域外定时任务） |
| 10 | 审计记录 | WORM | 仅追加（域外签名密钥） | 只追加、哈希链、密钥在域外 | 取证失效 | 链校验 + 签名校验（独立主机） |
| 11 | 快照 / 对象存储版本 | 对象存储 | 生命周期策略 | 受删除顺序覆盖 | DSR 漏删 | 版本枚举 + 删除报告逐版本条目 |
| 12 | 域内上报通道 | 反向通道 | 域内 | **不可信**：可伪造/丢弃/延迟 | 掩盖攻击 | 域外控制点自身记录（`SEC-071`） |
| 13 | MCP 远端内容（四通道） | 域内上下文 | 第三方服务器 | 未声明信任 ⇒ `untrusted` | 注入 | 信任级字段（Connector Registry）+ 通道过滤动作审计 |
| 14 | 模型输出 | 域内 | 模型 | 对抗输入 | 越权尝试 | 四条语义边界（§3）各自的拦截点 |

## 3. 四条安全语义边界（封闭集）

**判定标准**：任何被标注为「安全控制」的机制必须归入下表四条之一；归不进去 ⇒ 该机制**不得**作为安全控制，降级为 UX/正确性手段（`SEC-035`）。归入后必须写出「拦截点」，拦截点为空 ⇒ 降级为 `应当` 或删除（`SEC-003`、`SEC-016` 的口径）。

| # | 语义边界 | 定义（可判定） | 强制拦截点（唯一合法三类） | 明确**不是**该边界的手段 |
|---|---|---|---|---|
| **B1** | **工具不可达** | 工具名 ∉ `toolAllowlist` ⇒ 该工具不出现在模型可见工具集，且派发期调用被拒 | ① `ctx.tools.register` 唯一入口（可见性，preventive）；② 挂载前不插入工具行；③ 预设表收敛；④ 全局 `guard()`（执行期兜底，preventive，覆盖 scoped 注册） | 域内声明式"只注册 X"；参数 schema 校验；`restrict()`（全局调用抛错，不覆盖 scoped，`VER-001`）；域内过滤 |
| **B2** | **凭证不下发** | 域内不存在长期凭证；需要凭证的 connector 数据面托管；唯一例外按 `SEC-051` 登记 | 域外密钥库 + 凭证代理（以域身份查表）；容器环境白名单构造；就绪判据 5（无 credential provider 行） | 内核环境清洗启发式（`C46`，登记为"已知启发式、非控制"）；域内自证"我没拿凭证" |
| **B3** | **模式不超上限** | 单次调用的沙箱模式 ≤ `sandboxModeCeiling`；预设表收敛为单一预设，`danger-full-access` 与 `never` 不可达 | 域外策略/审批判定点；Profile 生成器（`PC-003`/`PC-004`）；就绪判据 4 | 会话内 `setSandboxMode` 写路径（须禁用）；`DSH_PERMISSION_MODE` 单靠环境变量；域内 `permission/preset` 事件 |
| **B4** | **租户边界** | 请求中的 `tenantId` == 域令牌中的 `tenantId`；跨租户文件/网络/进程/依赖不可见 | 域令牌签发与域外入站校验；容器/microVM 隔离；网络策略 | workspace 分区（域内 workspace 之间不是安全边界，`C44`）；preset/scope（非安全边界，`C17`/`C19`） |

### 3.1 语义边界的排除项（一经出现即判不通过）

| 被判为"安全控制"的机制 | 处置 |
|---|---|
| `validateArgs` / JSON Schema / 参数范围检查 | 归 UX 与正确性；**不得**声称防越权 |
| 运行期 deny 列表 | **不存在**此语义；`deny` 一律表达为"不进 `toolAllowlist`"（`SEC-030`） |
| `writeScopes` | 字段不存在；需要限制写入必须拆隔离组或独立域（`SEC-034`） |
| 域内注入过滤 | 对域内其他插件不构成强制（`C19`）；强制力只有"不挂载"+"入口拦截" |
| 域内 attest / 漂移上报 | detective；**不得**计入硬保证（`SEC-017`） |
| 沙箱 `enforcement` 自报 | 记录用；`enforcement != full` 只作打标（`SEC-097`） |

## 4. D15 边界：域内自报一律 detective

**判定标准**：抽取任一被标 preventive 或计入硬保证的条款，其拦截点必须落在 §1 的 A/B/C 三类之一，**且**其判定输入不得来自域内上报。违反即不通过（`SEC-002`）。

| 域内自报种类 | 等级 | 允许的用途 | **禁止**的用途 | 不一致时的处置 |
|---|---|---|---|---|
| `boot` / `heartbeat` attest 指纹 | detective | 与域外已知摘要比对；发现配置漂移 | 作为 ready 通过依据；作为任何能力的唯一拦截；作为"防篡改"证明 | 告警 → 重新签发 Profile 或走摘域流程（摘域动作单独审批） |
| 工具 schema 哈希、工具集指纹 | detective | 交叉核验；`tools/change` 触发比对 | 替代域外判定的工具清单 | 同上 |
| 漂移上报（未授权注册/工具出现） | detective | 触发摘域**流程** | 直接执行摘域（须单独审批） | 摘域审批通过后执行 |
| connector 生命周期变化上报 | detective（预期事件） | 冻结该 connector 新工具可见性 + 告警 + 自动重载 | 摘除整域 | 由 Connector 控制器重载（`SEC-021`） |
| 域内 `enforcement` 上报 | detective | 审计打标 | 作为沙箱有效性证明 | 与域外平台档位登记比对 |
| 域内 selfcheck（`{item, ok, detail}`） | detective | 交叉核验 `SEC-DOC-04` 的七条 | 替代域外七条判定 | 以域外判定为准；不一致即调查 |

**对外声明义务**：上述定性必须在合规材料中可判定地出现（`SEC-090`：域内上报可被伪造、丢弃或延迟；对账只能发现不一致，不能发现伪造）。逐字文本见 `SEC-DOC-10` §2。

## 5. 信任假设 → 拦截点对照（评审用核对表）

逐行核对：一行的「强制拦截点」为空，或指向域内自报 ⇒ 记不通过项。

| 假设 | 强制拦截点 | 拦截点性质 | 关联 `SEC-*` |
|---|---|---|---|
| 域内工具集 == `toolAllowlist` | 桥入口判定 + 全局 `guard()` | preventive | `SEC-005`、`SEC-012`、`SEC-029`、`SEC-038` |
| MCP 运行期新工具不得绕过 | 桥内同一入口（MCP 发现闸门） | preventive | `SEC-020`、`SEC-021` |
| Profile 层级合法 | 域外 Profile 生成器 | preventive | `SEC-010`、`SEC-006` |
| 制品未被替换 | 域外加载器包装层（哈希+签名） | preventive | `SEC-011` |
| 管理行不存在 | 挂载前不插入行 + 就绪判据 3 | preventive | `SEC-013`、`SEC-039` |
| 宽模式不可达 | 预设收敛 + 就绪判据 4 | preventive | `SEC-014`、`SEC-025`、`SEC-040` |
| profile 与制品不可写 | 容器挂载层 + 就绪判据 6 | preventive | `SEC-015`、`SEC-042` |
| 无长期凭证 | 域外密钥库/凭证代理 + 环境白名单 | preventive | `SEC-045`、`SEC-047` |
| 例外受控 | 数据面代理令牌校验（六元组 + audience）+ 登记上限 | preventive | `SEC-052`、`SEC-055` |
| 参数在审批前送达域外 | 桥上报道路 + 域外审批入站校验 | preventive | `SEC-058`、`SEC-059` |
| 审计最小集记不下即拒动作 | 六类动作各自的域外决策点 | preventive | `SEC-069`、`SEC-070` |
| 删除在全部副本完成 | 保留与删除服务 + 报告校验 | preventive | `SEC-083`、`SEC-087`、`SEC-104` |
| 配置漂移会被发现 | 域外 attest / 漂移判定 | **detective** | `SEC-017`、`SEC-018`、`SEC-027` |

## 6. 变更控制与本文件的失效条件

| 触发 | 动作 | 责任 |
|---|---|---|
| TCB 清单新增/删除条目 | 按 `SEC-00` §8 提变更；须同步 `SEC-DOC-03` 拦截点表与 `SEC-DOC-04` 证据来源 | 安全与合规架构师 |
| 前提 `P-1` 被推翻（出现第二注册路径） | `SEC-005`/`SEC-012`/`SEC-019` 及全部派生条款整体重评 | 总纲维护者 + SEC |
| 前提 `P-2` 被推翻（镜像或挂载层可被域内改写） | 全部 preventive 判据重评；本文件 §1 表格整体失效 | SEC |
| 前提 `P-3` 被推翻（内核改为读也受限） | `SEC-089`–`SEC-096` 披露条款可放宽，本文件 §2 第 8 行改写 | SEC + PRD |
| 内核升级（`GATE-006`） | 复核 `P-1`/`P-2`/`P-3` 与 §5 全表 | ENG + SEC |
