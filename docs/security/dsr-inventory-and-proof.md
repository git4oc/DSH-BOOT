## 1. 八类数据清单（封闭集；缺任一类即不通过）

| # | 数据类 | 位置 | 真源？ | 删除方式 | 责任组件 | 状态取值（报告中） | `SEC-*` |
|---|---|---|---|---|---|---|---|
| D1 | 会话事件日志 | 域卷 + 对象存储（异步复制） | 是（真源之一） | 停写取锁 → 墓碑 → 删主副本与副本 → 释放锁；对象存储生命周期 | 保留与删除服务 + 自建会话索引 | 已删除 | `SEC-078`、`SEC-082` |
| D2 | 附件 `attachments` | `<DSH_HOME>` **域卷**（固定，不落宿主共享目录） | 是 | 按 §2 选定策略执行（引用计数 **或** 抹除内容 + 保留占位）；目录随域销毁 | 保留与删除服务 + 域卷生命周期 | 已删除 / 已抹除（占位保留） | `SEC-079` |
| D3 | 溢出文件 `spill` | `<DSH_HOME>` 域卷（`spill.root` 固定到域卷） | 是 | 域外或定时任务清理；**不得**依赖内核一次性启动扫描 | 域外定时清理任务 | 已删除 | `SEC-080` |
| D4 | FTS 派生库 | `<DSH_HOME>` 域卷 | 派生（跨重启保留） | 随域卷删除；域内**不得**挂载 `dsh-session-query-sqlite` | 保留与删除服务 | 已删除 | `SEC-078`、`SEC-032` |
| D5 | 快照 / 对象存储版本 | 对象存储 | 是 | 纳入删除顺序；含不可变与合规锁模式的**解除流程** | 保留与删除服务 + 对象存储生命周期 | 已删除 / 已标记失效 | `SEC-081` |
| D6 | 容器临时层 | 容器运行时 | 否 | 域回收即销毁 | 域回收编排 | 已销毁 | `SEC-088` |
| D7 | 审计记录 | WORM | 追加型 | **假名化而非删除**（§4）；报告说明未删除类别与依据 | 保留与删除服务（假名化步骤） | **已假名化** / 保留 | `SEC-085`、`SEC-076` |
| D8 | workspace 文件与凭证引用 | 域卷 / 元数据库 | 是 | 文件随域的 workspace 卷处置；凭证引用删除映射，密钥材料按密钥库流程 | 保留与删除服务 + 密钥库 | 已删除 / 已吊销 | `SEC-078`、`SEC-088` |

**定位（受理→定位）**：定位**必须**经**域外自建会话索引**；**不得**依赖内核 `list()` 全量扫描（`SEC-086`）。判据：10 万会话规模的测试租户，定位在承诺时延内完成，输出会话数与预期一致。

**域卷处置**：域回收时对域卷执行**物理擦除或密钥销毁**，并记录所采方式（`SEC-088`）。方式登记字段：`{domainId, method: wipe|key-destroy, evidenceRef, at}`。

## 2. 附件去重粒度（二选一，必须显式登记）

| 模式 | 配置值 | 行为（可判定） | 删除报告写法 |
|---|---|---|---|
| 引用计数 | `attachmentDeletionMode = refcount` | 同一内容被 N 个会话引用；删一个会话 ⇒ 内容仍在、计数减一；计数归零 ⇒ 内容删除 | 状态 = `已删除`（计数归零）或 `保留`（计数 > 0）+ 计数值 |
| 抹除占位 | `attachmentDeletionMode = scrub` | 删除即抹除内容、保留引用占位；报告列出占位标识 | 状态 = `已抹除（占位保留）` + 占位 ID |

- 配置项为**必填**且进入 Profile 校验；未登记 ⇒ 拒绝签发。
- 整体删除租户 ⇒ 目录随域销毁（两种模式都必须成立）。

## 3. 四件套证明（`SEC-083`）

| # | 组成 | 生成者 | 必含字段 | 校验方式 |
|---|---|---|---|---|
| P-1 | **删除清单** | 保留与删除服务 | `{dsrId, tenantId, scope, items[]}`；`items[]` 覆盖 §1 的 D1–D8，每项 `{class, location, status, basis, timestamps{}}` | 逐类核对：八类均在；无 "未列出" 类 |
| P-2 | **墓碑** | 删除流程（停写后立即写） | `{dsrId, tenantId, workspaceId, sessionId, turnId, 事件类型, 丢弃/删除量估算, 墓碑时刻}`；另含对账墓碑 `reconciled:false` 语义 | 墓碑计数与删除计数一致；可按 `turnId` 检索 |
| P-3 | **删除报告** | 保留与删除服务 | 见 §3.1 模板；**逐副本**含区域标识、删除时间、校验值 | 报告字段完整性校验 + 副本数比对 |
| P-4 | **哈希链证明** | WORM 审计 + 导出服务 | `{recordCount, chainHead, chainTail, signatureRef, firstCoveredAt, lastCoveredAt}` | 在**隔离主机**上运行独立校验器；未篡改通过、改动 1 byte 失败 |

### 3.1 删除报告模板（逐类 + 逐副本）

| 字段 | 必填 | 说明 |
|---|---|---|
| `reportId` | 是 | 唯一，形如 `DR-<dsrId>` |
| `dsrId` | 是 | DSR 受理号 |
| `tenantId` | 是 | — |
| `requestedAt` / `acceptedAt` | 是 | UTC |
| `tombstonedAt` | 是 | ≤ `acceptedAt + 1 h` |
| `completedAt` | 是 | ≤ `acceptedAt + 24 h` |
| `revocationWindowEndsAt` | 是 | `acceptedAt + 7×24 h` |
| `items[]` | 是 | 八类各一行：`{class, location, status, basis, deletedAt, evidenceRef}` |
| `replicas[]` | 是 | 每副本一行：`{replicaId, region, dataClass, deletedAt, checksum, status}`（`SEC-104`） |
| `pseudonymization` | D7 假名化时必填 | `{algorithm, keyId, appliedAt, affectedRecords, irreversible: true}` |
| `exceptions[]` | 是 | 未删除/保留项及依据（如 `audit-retention`）；无则空数组 |
| `proofRefs` | 是 | 四件套其余三项的引用（P-1/P-2/P-4） |
| `generatedBy` / `generatedAt` | 是 | 服务标识与时间 |

**报告不通过的判定**：① 八类缺任一；② D7 状态写作 `已删除`；③ 任一副本缺区域标识；④ `completedAt - acceptedAt > 24 h`；⑤ `exceptions[]` 为空但存在审计记录。

## 4. 假名化步骤（`SEC-085`，固定顺序）

| 步 | 动作 | 判定/参数 |
|---|---|---|
| S-1 | 抽出计费与审计所需的**假名化聚合** | 聚合维度 `(tenantId, turnId, 用量类别)`；聚合值必须在删除前落库 |
| S-2 | 定位主体标识字段 | 字段封闭集：`userId`、`userEmail`、`userName`、`phone`、`subjectId`、`externalSubjectId`、`actorId`、`ip`（若记录）、`displayName` |
| S-3 | 计算不可逆假名 | `pseudonym = HMAC-SHA-256(pseudonymKey, tenantId ‖ 0x1F ‖ subjectId)`，取前 32 位小写十六进制 |
| S-4 | 就地替换（只追加存储的合规例外） | 替换动作本身必须写一条 `security.pseudonymized` 审计事件（含 `dsrId`、字段清单、记录数、`keyId`），并进哈希链 |
| S-5 | 删除反向映射 | 平台**不得**保存"假名 → 主体"映射；`pseudonymKey` 由域外密钥库持有，**不得**导出到域内 |
| S-6 | 记录不可逆声明 | 报告中 `pseudonymization.irreversible = true` 且给出 `keyId` |
| S-7 | 校验 | 对抽样记录断言：主体标识字段已无原始值，且 `tenantId`、时间、用量仍可用于对账 |
| S-8 | 对账可完成性验证 | 删除后 T+24 h 对账仍可完成，差异率 ≤ 0.01%（`REL-101`） |

**禁止**：把 D7 记录整体删除；把 `userEmail` 等字段置空而不假名化（会破坏对账可解释性）。

## 5. 生效时延与撤销窗口（`SEC-084`）

| 时点 | 必须成立的状态 | 检查方式 |
|---|---|---|
| T+0 | `DELETE` 确认（二次确认完成）；进入 `pending` | 受理记录 |
| T+0 … T+1 h | 进入**墓碑**状态：对用户不可读 | `GET` 会话/文件入口返回 `404`/`410`；墓碑记录存在 |
| ≤ T+24 h | 全清单（D1–D8）完成删除或假名化；报告可出具 | 报告 `completedAt` − `acceptedAt` ≤ 24 h |
| 窗口内（≤ 7×24 h） | `撤销`可用；撤销后 workspace 恢复**可写**、文件/会话历史/快照可读 | 第 3 天撤销成功并恢复 |
| T+7×24 h 之后 | 撤销入口关闭；请求被拒并给出明确原因；方可执行物理擦除步骤 | 第 8 天撤销被拒；物理擦除时间戳晚于窗口结束 |
| 全流程 | 每步有可查询时间戳（`PRD-029`） | 报告四步时间戳齐备 |

**删除顺序（不得重排）**：`停写（取锁）→ 墓碑 → 删数据 → 释放锁`。与迁移竞争时：删除进入等待或迁移被拒，**不得**出现并发写与删除交错（`SEC-082`）。测试：在一次迁移进行中发起删除，日志中四步顺序可验。

## 6. 逐副本与区域（`SEC-087`、`SEC-104`）

| 要求 | 判定 |
|---|---|
| 报告覆盖全部副本 | 主副本 + 跨区副本 + 快照/对象存储版本，逐副本列出删除时间与校验值 |
| 区域标识 | 每副本行必须含 `region`；缺 ⇒ 报告不通过 |
| 未删除副本 | 存在任一未删除副本 ⇒ 报告不通过，不得出具 |
| 合规锁阻塞 | 被锁阻塞且**未登记**的版本 ⇒ 不通过；已登记的须列解除方式 |

## 7. 验收用例

| 用例 | 构造 | 断言 | 归属门禁 |
|---|---|---|---|
| U-01 | 测试租户发起 DSR，逐类核对报告 | 八类均有条目、位置、状态与依据 | `GATE-005` 条件 2 |
| U-02 | 同一内容被两会话引用，删其一；再整体删租户 | 按所选策略给出确定结果；租户删除后目录随域销毁 | `SEC-079` |
| U-03 | 造出 spill 文件后**不重启**域，等待超过保留期 | 文件被域外/定时任务删除，无残留 | `SEC-080` |
| U-04 | 迁移进行中发起删除 | 无并发交错；四步顺序可验 | `SEC-082` |
| U-05 | 1 h / 23 h / 第 3 天 / 第 8 天四点取样 | 1 h 内不可读；23 h 内全清单完成；第 3 天撤销成功；第 8 天撤销被拒 | `PRD-030`、`SEC-084` |
| U-06 | 含审计记录的租户 DSR 后做一次对账 | D7 为已假名化；对账无无法解释缺口 | `SEC-085`、`REL-101` |
| U-07 | 10 万会话租户 DSR | 定位经自建索引；会话数与预期一致；**不得**调用内核 `list()` | `SEC-086` |
| U-08 | 含主副本 + 跨区副本的租户删除 | 报告逐副本含区域标识、删除时间与校验值 | `SEC-087`、`SEC-104` |
| U-09 | 销毁域后检查临时层与卷 | 临时层不可恢复；卷按登记方式处置且记录可查 | `SEC-088` |
| U-10 | 篡改取证包 1 byte 后重跑独立校验器 | 校验失败；未篡改时通过并输出链首尾摘要 | `SEC-072`、`SEC-074` |
