## 2. 逐字文本

> 下列文本为**必须逐字出现**的最小内容。允许在同一材料中增加解释，但**不得**删改、缩写或改写成"意思相近"的说法。字符串比对以规范化空白后的文本为准。

### 2.1 读不隔离（`SEC-089`，`COPY-001`）

```
同一个工作区里的会话可以互相看到文件；不同工作区之间，平台不保证互相看不见——需要互相看不到的人/团队，请放在不同租户或不同隔离组下。
```

| 判定 | 内容 |
|---|---|
| 实测 | 在 workspace A 的会话内读取 workspace B 的文件：**必须成功**；若实测失败（读被隔离），本披露须按 `P-3` 复核后放宽 |
| 一致性 | 材料文本与实测行为必须一致；不一致 ⇒ 披露不通过 |
| 附加要求 | 帮助文档同条目须给出"如何申请独立租户 / 独立隔离组"的操作路径链接 |

### 2.2 同一租户内部假定互信（`PRD-020` 承接）

```
同一租户内部假定互信。需要互相看不到的人/团队，请放在不同租户或不同隔离组下。
```

### 2.3 审计不可防伪造与对账边界（`SEC-090`，`COPY-021` + `COPY-029`）

必须**同时**出现下列允许承诺与边界句，且全文不得出现禁用词。

`COPY-021` 原文（逐字，比对基准）：

```
审计记录为追加型写入，哈希链可发现篡改，安全事件的权威源在域外。对账可以发现不一致，不能发现伪造。
```

补充句 `COPY-029`（`SEC-090` 另要求披露"域内上报可被伪造/丢弃/延迟"；**须与 `COPY-021` 同页共现**）：

```
域内上报只作补充，可被伪造、丢弃或延迟。
```

| 项 | 判定 |
|---|---|
| 三要素共现 | 「追加型写入」「哈希链可发现篡改」「权威源在域外」必须在**同一材料页**出现 |
| 边界句 | 「对账可以发现不一致，不能发现伪造。」必须出现，**不得**省略 |
| 禁用词（全文检索命中即阻断） | `不可篡改`、`防篡改`、`防伪造`、`tamper-proof`（完整清单见 §4） |
| 权威源清单（可选附录） | 反向网关、凭证代理、MCP 出站代理、attest 服务、Session Router |

### 2.4 Windows 三项残留（`SEC-091`、`SEC-092`、`SEC-093`；文案 `COPY-030`）

> 逐字文本基线为 `COPY-030`（`PRD-DOC-01` §3，**已登记**）。与 `COPY-020` 同页时**不得**合并为一段以省略任一项。

```
在 Windows 档下：①平台对工作区目录树授予的 Low 完整性标签会加宽该目录树，同一用户的其他低完整性进程可以在工作区内写入与删除文件，该风险在 Windows 上无排除手段；②平台对客户真实目录的安全描述符编辑会按设计保留，包括对普通删除路径语义的改变；③继承的工作区授权会传播到既有硬链接上，同一底层对象可经外部别名写入。
```

| 子项 | 单独的可判定事实 | 实测方法 | `SEC-*` |
|---|---|---|---|
| ① Low 标签加宽 | 同用户其他 Low-IL 进程在工作区**可写可删** | 用另一 Low-IL 进程在工作区写入与删除文件，记录结果 | `SEC-091` |
| ② DACL 永久改写 + 删除语义变化 | 授权前后 DACL 快照不同；`FILE_DELETE_CHILD` 对 world 被拒；用户自己的普通删除路径行为改变 | 记录授权前 DACL 与一次普通删除行为，跑完授权后再测 | `SEC-092` |
| ③ 硬链接别名可写 | 工作区外文件建硬链接后，经外部别名写入成功 | 建硬链接 → 跑授权 → 经外部别名写入 | `SEC-093` |

**临时 vs 驻留的准确表述**（不得写成"物理不可能撤销"）：

```
临时授权与 Low 标签可由模块 dispose() 撤销；工作区安全描述符编辑按设计保留。
残留驻留期 = 卷/目录生命期；销毁域即销毁卷可消除工作区残留。
手工 icacls 无法回收（ERROR_NONE_MAPPED 1332），经该模块可以。
```

### 2.5 Windows 部署形态（`COPY-020`，`PRD-025` 承接，合同逐字）

```
Windows 档下，平台对客户本机目录的安全描述符编辑会按设计保留（包括对普通删除路径语义的改变），并会在工作区目录树中形成同用户其他低完整性进程可写可删的加宽面；该风险在 Windows 上无排除手段。客户须选择“随域销毁的独立卷”或改用 microVM 部署形态。
```

| 判定 | 内容 |
|---|---|
| 配置附录 | 每客户登记所选形态（`独立卷` / `microVM`），字段见 §3.4 |
| 硬约束 | 未选择独立卷或 microVM ⇒ **不出具 Windows 档报价单**；域挂载宿主共享目录 ⇒ 拒绝 ready（`SEC-094`） |
| 存量客户 | 版本发布后 30 天内完成告知并留档 |

### 2.6 公网工具（`SEC-095`，`COPY-022`）

```
域内不提供公网访问工具；公网访问仅经域外代理并施加策略、DLP 与硬审计。
```

| 判定 | 内容 |
|---|---|
| 工具清单 | 域内活动工具集与 Profile `pluginSet` **不含** `dsh-tool-web` / `web_fetch` |
| 若保留（例外路径） | 必须同时具备四项：已披露条目 + 域外 DLP + 硬审计 + 配额；缺一即不通过 |
| 展示 | 演示环境不得复现"模型自行把数据发往任意公网 URL"的路径 |

### 2.7 子代理内审批不可用（`SEC-096`，`COPY-008`）

```
本会话内由子代理发起的工具调用不可审批：需要审批的工具在子代理内会被直接拒绝
```

| 判定 | 内容 |
|---|---|
| 实现 | `toolFilter` 由 Profile 依 `toolAllowlist` 派生；子代理内调用 `requireApproval` 工具 ⇒ 硬拒且**不产生审批请求** |
| 实测 | 与说明文本**逐字一致**；出现"子代理内可审批"的路径即不通过 |

### 2.8 沙箱等级与打标（`SEC-097`；文案 `COPY-031`）

> 逐字文本基线为 `COPY-031`（`PRD-DOC-01` §3，**已登记**）。

```
本平台的沙箱只管辖文件写的效果；它不表达网络、进程、系统调用、设备与凭据限制，对域内对抗者不成立。Windows 档的执行报告为 partial。执行报告 enforcement 不等于 full 的时段，会在审计记录上打标。
```

| 判定 | 内容 |
|---|---|
| 三项齐备 | ① 只管辖文件写；② 对域内对抗者不成立；③ Windows 报 `partial` |
| 打标 | 抽查会话审计记录：Windows 上带 `enforcement` 标记；`enforcement != full` 必打标 |

## 3. Windows 已修改路径清单 + 卸载复原流程 + 责任人（交付物 12）

### 3.1 已修改路径清单（模板；每次挂载必须逐路径填写）

| 列 | 必填 | 说明 |
|---|---|---|
| `path` | 是 | 被修改的绝对路径（目录树用 `…\**` 表示整树） |
| `modificationType` | 是 | `ACE-grant` / `deny-entry` / `low-integrity-label` / `workspace-security-descriptor-edit` / `hardlink-inheritance` |
| `appliedAt` | 是 | UTC |
| `appliedBy` | 是 | 组件名与版本 |
| `revertible` | 是 | `dispose-revertible` / `retained-by-design` |
| `baselineRef` | 是 | 挂载**前**采集的 DACL/标签基线工件路径与哈希 |
| `postMountHash` | 是 | 挂载后同对象的安全描述符哈希 |
| `restoreAction` | 是 | `dispose` / `restore-from-baseline` / `destroy-volume` / `none(by design)` |
| `evidenceRef` | 是 | 记录文件路径 |

**完整性判据**：授权过程中实际被写的对象集合 ⊇ 清单条目集合；清单缺任一条目 ⇒ `SEC-098` 不通过。

### 3.2 卸载与复原流程（固定步骤，逐步骤断言）

| 步 | 动作 | 断言（不通过即阻断） |
|---|---|---|
| R-1 | 停写：拒绝该域新轮次，排空在途轮次 | 无在途写句柄 |
| R-2 | 由模块调用 `dispose()`，撤销临时授权与 Low 标签 | 返回成功；记录返回码 |
| R-3 | 对 `retained-by-design` 项：按 §3.1 的 `restoreAction` 从基线恢复安全描述符 | 恢复后 DACL 哈希 == `baselineRef` 哈希（除已披露的按设计保留项） |
| R-4 | 复算修改路径集合与基线快照比对 | 差异集合 == 已披露保留项集合；出现未披露差异 ⇒ 不通过 |
| R-5 | 域卷处置：物理擦除或密钥销毁，并记录方式 | 记录含 `{method, at, evidenceRef}` |
| R-6 | 判定：手工 `icacls` 不参与复原 | 复原流程中**不得**出现手工 `icacls` 作为唯一手段 |
| R-7 | 留证归档 | 七项工件齐备（§3.3） |

**实测门禁**：在测试环境完成一次「挂载 → 卸载」完整循环；复原后 DACL 与基线一致（除已披露保留项）。该实测是 `GATE-002` 条件 7/9 的证据。

### 3.3 留证清单（`SEC-098` 判据）

```
① 已修改路径清单（填毕）
② 基线 DACL/标签快照（含哈希）
③ 挂载后安全描述符快照（含哈希）
④ dispose() 调用记录与返回码
⑤ 复原后快照与基线比对报告
⑥ 域卷处置记录（方式/时间/证据引用）
⑦ 责任人签署记录（§3.4）
```
